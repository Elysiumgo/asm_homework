# 作业 5：递归调用——Fibonacci 数列

## 1. 完成内容

- 从键盘输入 `n`，范围为 `1~100`。
- 根据输入递归计算并输出第 `n` 个 Fibonacci 数 `F(n)`。
- 汇编程序通过 `CX` 传递递归参数，并在每层用栈保存 `CX` 和返回地址。
- `.STACK 400H` 分配 1024 字节栈空间，能够覆盖 100 层递归。
- 使用 22 位十进制数组保存大整数，可正确输出 `F(100)`，避免寄存器溢出。
- 提供等价 C 程序和 C 程序的实际反汇编注释。

## 3. 递归和栈的设计

`FIB_RECURSIVE` 的输入参数放在 `CX` 中。每层执行顺序如下：

1. `PUSH CX` 保存本层参数；
2. `DEC CX` 后 `CALL FIB_RECURSIVE`；
3. 到达 `CX=0` 后开始逐层返回；
4. `POP CX` 恢复本层参数，执行一次递推计算；
5. `RET` 从当前层返回。

递归完全返回后，`NUM_A` 中保存 `F(n)`，主程序只输出这一个结果。

每个尚未返回的递归层主要占用 4 字节：2 字节返回地址和 2 字节保存的 `CX`。100 层约占 400 字节。考虑程序调用其他过程时还会临时压栈，本程序分配 1024 字节，留有充足余量，不会发生栈溢出。

## 4. 调试过程记录

### 输入检查

使用 DOS `INT 21H/AH=0AH` 读取字符串，再逐字符转换成十进制数。测试了边界值 `1`、`100`，并检查 `0`、`101`、字母等非法输入会显示错误信息。

### 大数处理

最初需要先确认数据范围：`F(100)=354224848179261915075`，已经超过 64 位无符号整数。程序没有直接用 `AX` 保存结果，而是让 `NUM_A`、`NUM_B` 和 `NUM_TEMP` 各保存 22 个十进制位，低位在前。`ADVANCE_FIB` 逐位相加并处理进位。

### 递归和栈观察

在 DEBUG 中进入 `FIB_RECURSIVE` 前记录 `SP`，单步执行 `PUSH CX` 后 `SP` 减 2，执行 `CALL` 进入下一层时返回地址再次入栈，`SP` 再减 2。返回阶段执行 `POP CX` 和 `RET` 后，`SP` 逐步恢复。程序结束前后栈顶能够回到调用前的位置，说明压栈和出栈保持平衡。

### 寄存器保护问题及修正

第一次运行时，输入值虽然由 `PARSE_INPUT` 正确放入 `AX`，但随后为了打印标题执行了 `INT 21H/AH=09H`，中断调用改变了 `AX`。若在中断后才执行 `MOV CX,AX`，递归次数就会错误，程序会输出远超 `n` 项的数据。修正方法是在调用输出中断前先执行 `MOV CX,AX`，把递归参数保存在 `CX` 中。这个问题说明：寄存器中的临时结果跨越过程调用或系统调用时，必须先保存到不会被破坏的位置。

### 结果核对

- 输入 `1`：输出 `F(1)=1`。
- 输入 `10`：输出 `F(10)=55`。
- 输入 `100`：输出 `F(100)=354224848179261915075`。
- C 版与汇编版在相同输入下输出一致。

## 5. DOSBox 编译与运行

将本目录挂载为 DOSBox 的 C 盘后执行：

```text
MASM FIBREC.ASM;
LINK FIBREC.OBJ;
FIBREC.EXE
```

出现 `Input n (1-100):` 后输入测试值，例如 `10`。

## 6. DEBUG 单步观察方法

```text
DEBUG FIBREC.EXE
U
R
T
```

先用 `U` 找到主程序中的 `CALL FIB_RECURSIVE`，用 `T` 单步进入。每执行一次 `PUSH`、`CALL`、`POP`、`RET` 后输入 `R`，重点记录 `CX`、`SS`、`SP` 的变化。也可以使用 `D SS:SP` 查看当前栈顶附近保存的参数和返回地址。

## 7. 学习心得

本题说明递归不仅是高级语言概念，底层依靠 `CALL` 保存返回地址、`RET` 取回返回地址，并由程序员负责保护仍需使用的寄存器。递归层数决定最大栈占用，因此写递归程序前必须估算每层压栈字节数。另一个重要问题是数据范围：即使控制流程正确，寄存器容量不足也会产生错误；对 `n=100` 的 Fibonacci 数必须采用多精度表示。
